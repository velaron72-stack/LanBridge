# LanBridge

Виртуальная локальная сеть между двумя Android-устройствами без сервера и без root. Игры и приложения, которые работают только по LAN, видят друга как устройство в той же сети (unicast, broadcast, multicast).

Роли «хост/клиент» нет: оба устройства выполняют один и тот же код, «инициатор» рукопожатия выбирается автоматически сравнением открытых ключей.

## Использование

1. Оба: «Создать код».
2. Обменяться кодами (текст или QR), вставить код друга.
3. Оба: «Подключиться» (с разницей не больше минуты). Опционально — общий пароль комнаты.
4. После статуса «Подключено» запускать игру. «Проверка LAN» показывает, проходят ли unicast, broadcast и multicast.

## Сборка

GitHub: залить содержимое репозитория, открыть Actions → Build APK → artifact `LanBridge-apk` (подписанный release APK). Ключ подписи лежит в `keystore/` (постоянный, чтобы новые сборки ставились поверх старых; проект не публичный).

Локально: JDK 17, Android SDK 35, NDK 26.3.11579264, CMake 3.22.1, Gradle 8.9.

```bash
gradle :app:assembleRelease
```

## Устройство

| Слой | Файлы | Задача |
|---|---|---|
| Native (C++17, без зависимостей) | `app/src/main/cpp` | криптография, формат кода, STUN, рукопожатие, hole punching, пересылка пакетов TUN ↔ UDP |
| Kotlin core | `core/` | JNI, настройки, состояние UI, проверка LAN |
| VPN-служба | `vpn/TunnelVpnService.kt` | TUN-интерфейс, `protect()` сокета, foreground-уведомление, wake/wifi lock |
| UI (Compose) | `ui/` | код/QR, статус, настройки, журнал, справка по фоновой работе |

Протокол: Noise_KK-подобное рукопожатие (X25519, BLAKE2s, ChaCha20-Poly1305) с PSK из пароля комнаты, защита от повторов (окно 2048), смена ключей каждые ~2 минуты, keepalive, измерение RTT. Код соединения: версия, срок, открытый ключ, тип NAT, имя, до 8 адресов, контрольная сумма. Виртуальная сеть `192.168.x.0/24` выбирается детерминированно и не пересекается с реальными адресами обоих устройств. Адрес источника переписывается с пересчётом контрольных сумм IP/TCP/UDP.

В TUN маршрутизируются только виртуальная подсеть, `224.0.0.0/4` и `255.255.255.255/32`; остальной трафик телефона не затрагивается.

## Тесты нативного ядра

```bash
bash native-tests/run.sh   # g++, ASan + UBSan, около 25 с
```

Проверяются: известные ответы (RFC 7693, 7748, 8439, независимые эталоны), рукопожатие (подмена, неверный PSK, привязка ответа), окно повторов, формат кода и фаззинг декодера, STUN через локальный mock, два движка в одном процессе через loopback: unicast, broadcast, multicast, перезапись адреса источника, MTU-пакеты, отбрасывание чужого трафика, 3000 мусорных датаграмм, выход друга, неверный пароль, таймаут и повтор, смена ключей под нагрузкой (потерь нет).

## Ограничения

- Прямое соединение невозможно, если NAT симметричный у обеих сторон (часть мобильных операторов). Обход: один Wi-Fi или точка доступа.
- IPv4 и уровень IP без root: игры, жёстко привязанные к интерфейсу Wi-Fi или использующие не-IP протоколы, работать не будут. Другой VPN одновременно включить нельзя.
- Производители (Xiaomi, Huawei/Honor, Oppo/Realme, Vivo, Samsung) агрессивно убивают фоновые службы: нужны автозапуск и снятие ограничения батареи (кнопки в справке).
- Android-часть (Gradle, CMake/NDK, Kotlin, Compose) в окружении разработки не собиралась и на устройстве не запускалась; проверена только нативная логика на хосте. Первая сборка в Actions — реальная проверка.
